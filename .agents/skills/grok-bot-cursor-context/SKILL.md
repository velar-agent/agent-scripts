# Grok Bot 사용량과 토큰 추출 맥락

확인일: 2026-11-15. 코드와 주석만으로 알 수 없는 사용자 요청 배경, 관측 결과, 검증 한계 18개를 기록합니다. 구현 상세는 [사용량 스크립트](../../../grok-bot-cursor-usage.sh), [macOS 추출기](../../../grok-bot-cursor-token-from-macos-keychain.sh), [Linux 추출기](../../../grok-bot-cursor-token-from-linux.sh)를 확인해 주세요. 당시의 계정·버전·수치를 현재 상태로 간주하지 않습니다.

1. **조회 대상과 인증의 검증 범위:** 사용자가 요청한 대상은 데스크톱 Grok Bot의 계정 사용 한도입니다. 기존 `grok-billing.sh`가 다루는 Grok Build와 인증 경로가 다릅니다. 이번에 성공을 확인한 인증은 Grok Bot에 저장된 Cursor 액세스 토큰이며, 일반 xAI API 키나 Grok Build 토큰으로 이를 대체할 수 있는지는 검증하지 않았습니다.

2. **명칭의 출처와 의도:** 사용자는 사용량 파일을 `grok-bot-cursor-usage.sh`로 작성하도록 지정했습니다. 추출기의 초기 이름 `grok-bot-cursor-token.sh`는 모호하다며 macOS 키체인이 이름에 드러나길 원했고, 최종 이름 `grok-bot-cursor-token-from-macos-keychain.sh`를 직접 제안해 변경을 요청했습니다. 재명명할 때 이 사용자 선택을 고려해 주세요.

3. **토큰 원문 출력은 사용자 요청:** 사용자는 추출 스크립트를 작성하면서 “echo로 찍도록 해줘”라고 명시했습니다. 토큰을 한 줄로 받아 환경변수나 다른 명령에 연결하는 사용 목적이 있으므로, 후속 수정에서 성공 안내문이나 마스킹된 값으로 출력을 바꾸지 않습니다. 이는 추출기를 직접 실행하는 출력에 관한 요구이며, 진단 로그에 인증 정보를 남기라는 요청은 아닙니다.

4. **사용량 옵션 제거의 범위:** 사용자는 `grok-bot-cursor-usage.sh --help`를 제시하며 `--timeout` 플래그를 빼 달라고 요청했습니다. 이 요청은 사용량 조회기의 CLI에 관한 것이며, 키체인 접근 제한 시간까지 제거하라는 요구는 아니었습니다. 다른 스크립트와 옵션을 통일한다는 이유로 사용량 조회기에 해당 플래그를 복원하지 않습니다.

5. **Windows 요청의 완료 범위:** 사용자는 Windows에서도 추출할 수 있는지 질문한 뒤, 다른 코딩 에이전트가 구현할 수 있도록 관련 문서를 기록해 달라고 요청했습니다. 이번 작업은 [Windows 구현 안내](../../../docs/grok-bot-cursor-token-windows.md)를 남기는 데까지 진행했습니다. Windows 구현 언어와 파일명은 사용자가 확정하지 않았으며, 문서의 PowerShell 파일명은 제안입니다.

6. **설치본 조사 기준:** macOS에서 조사한 Grok Bot은 1.1.0이고, 포함된 Electron Framework의 `CFBundleVersion`은 43.8.9였습니다. 근거는 설치본의 plist와 `Contents/Resources/app.asar`입니다. 번들의 `dist/electron-main/main-core.cjs`에서 인증 저장소와 `safeStorage` 처리를, `main.cjs`에서 데이터 경로 설정을 확인했습니다. 재조사할 때 버전과 번들 구조가 유지된다고 가정하지 않습니다.

7. **macOS 실계정 검증:** 가상 표본 외에 실제 키체인에서 토큰을 추출하고, 그 토큰으로 사용량 API의 HTTP 200과 JSON 응답을 확인했습니다. 환경변수로 전달한 토큰을 이용한 사용량 조회도 성공했습니다. 이는 당시 설치본과 로그인 계정에 대한 검증이며, 저장된 토큰의 현재 유효성을 보장하지 않습니다.

8. **49% 문의의 실제 표본:** 사용자는 화면에 주간 한도 49% 사용으로 표시되는데 API 값이 이상하지 않으냐고 질문하며 `usagePercent: 49.17301`을 제시했습니다. 이 값은 약 49.17% 사용으로 해석되어 화면의 정수 표시와 부합했습니다. 이 표본을 0~1 비율로 오해해 100을 곱하지 않습니다. 화면의 일반적인 반올림·절삭 알고리즘까지 검증한 것은 아닙니다.

9. **주간 기간과 날짜 차이의 근거:** 같은 사용자 응답의 기간은 `2026-11-10T17:49:23.684Z`부터 `2026-11-17T17:49:23.684Z`까지 정확히 7일이었습니다. 초기화 시각을 당시 현지 시간대인 Asia/Seoul로 바꾸면 11월 18일 02:49가 됩니다. 이 관측은 해당 표본의 주간 표시를 뒷받침하며, 다른 요금제의 모든 기간을 확인한 결과는 아닙니다.

10. **Grok 요금제와 Cursor 요금제의 공존:** 동일 실응답에 `grokPlanLabel: "X Premium+"`, `cursorPlanName: "Free"`, `hasNonZeroIncludedLimit: true`가 함께 있었습니다. Cursor 청구 브랜드와 통합 플랜 안내도 반환됐습니다. 따라서 이 계정에서 Cursor의 Free 표기만으로 Grok Bot 한도가 없거나 다른 계정을 조회했다고 판단하지 않습니다.

11. **키체인 제한 시간 실패의 관측:** 실제 추출을 처음 10초 제한으로 시도했을 때 시간 초과가 발생했고, 이후 30초 제한으로 재시도했을 때 성공했습니다. 지연의 정확한 원인이나 프롬프트 처리 시점은 확인하지 않았습니다. 짧은 제한에서의 실패만으로 암호화 형식이나 저장된 키가 틀렸다고 결론내리지 않습니다.

12. **가상 테스트와 실계정 검증의 구분:** 사용량의 오류 응답·누락값·체험·공동 한도 분기와 추출기의 활성 계정 선택·이전 저장 형식·손상된 입력 등은 가상 표본으로 시험했습니다. 실제 macOS 계정에서는 `v10` 암호문 추출과 사용량 조회를 확인했습니다. 가상 테스트 통과를 체험 계정, 기업 공동 한도, 모든 저장 형식의 실계정 검증으로 확대하지 않습니다.

13. **Windows 경로와 동작은 미검증:** Windows 안내의 `%APPDATA%` 아래 파일 위치는 Electron의 경로 규칙과 macOS 앱 이름으로 추정한 후보입니다. 실제 Windows의 인증 파일, 복호화, API 인증은 이번 작업에서 확인하지 않았습니다. Windows 작업을 시작할 때 [구현 안내](../../../docs/grok-bot-cursor-token-windows.md)의 파일 조사와 완료 기준을 읽고 대상 PC에서 확인해 주세요.

14. **Windows 복호화 조사의 근거:** Electron 43.8.9의 동기 `safeStorage` 구현은 Chromium에서 제거된 동기 백엔드를 패치로 복원합니다. Windows 절차의 근거는 해당 태그의 `revert_oscrypt_remove_sync_backend.patch`이며, 이 구현의 `v10`은 macOS의 CBC 방식과 달리 DPAPI로 보호한 키를 사용하는 AES-GCM입니다. 같은 접두사만 보고 macOS 함수를 이식하면 안 됩니다. 출처 링크와 구체적인 절차는 [구현 안내의 Windows 복호화 절](../../../docs/grok-bot-cursor-token-windows.md#windows-복호화-구현의-근거와-절차)에 모아 두었으며, 이는 소스 근거와 Windows 실검증을 구분하기 위한 기록입니다.

15. **Linux 설치본과 실제 저장 표본:** Linux 작업 환경에 설치된 Grok Bot은 1.1.0이었습니다. 실제 인증 파일은 `/home/box/.config/Grok Bot/sand-secrets.json`에 있었고, `version: 1` 형식에 계정 1개가 저장되어 있었습니다. 활성 계정 토큰은 `scoped:v1:`·`plaintext:v1:` 래퍼가 없는 `v10` 암호문이었습니다. 이 경로와 계정 수는 해당 환경의 관측값이며 다른 사용자나 설치본에 고정하지 않습니다.

16. **Linux 검증 환경의 의존성:** 당시 `python3`와 Python `cryptography` 패키지는 설치되어 있었지만 `secret-tool`과 `kwallet-query`는 없었습니다. 이 환경에서 실제 `v10` 토큰 추출에 성공했으므로 해당 성공을 OS 키링 조회 도구가 설치되거나 동작했다는 근거로 해석하지 않습니다.

17. **Linux 실계정 검증:** Linux 추출기로 실제 활성 계정 토큰을 추출하고, 환경변수로 사용량 조회기에 전달해 사용량 API의 HTTP 200과 JSON 응답을 확인했습니다. 실행 전후 인증 파일을 바이트 단위로 비교해 내용이 동일함을 확인했습니다. 토큰 원문과 계정 응답 본문은 작업 로그에 출력하지 않았으며, 이 결과는 당시 계정의 인증 성공을 확인한 것입니다.

18. **Linux 테스트 통과와 검증 한계:** Linux 추출기 자동 테스트 18개가 통과했습니다. 실제 계정에서는 `v10` 추출과 사용량 조회를 검증했고, GNOME Secret Service·KWallet의 `v11` 경로는 가상 암호문과 모의 조회 도구로 검증했습니다. 실제 GNOME/KWallet 세션에서의 잠금 해제, 권한 안내, 저장 키 조회가 성공했다고 확대하지 않습니다.
